title: Quickstart

You have a test suite — Playwright, WebdriverIO, Jest, or Vitest — and
you want to see its results on a Brittle dashboard. This page is the
shortest path.

## You'll need

- A working test suite for one of the supported frameworks.
- A Brittle hub. Two options:
  - The hosted demo at [brittle.dev](https://brittle.dev) — fastest
    way to see what the dashboard looks like.
  - A self-hosted hub. [Installation](/docs/installation) is the
    Docker Compose walkthrough — about five minutes.
- A project token. In the dashboard, click
  **Manage → Projects**, pick your project, open the **Tokens** tab,
  and mint one of type **service**. Copy it immediately — the
  plaintext is shown once.

## Install the reporter

Pick the package that matches your framework:

```bash
# Playwright
pnpm add -D @brittlehq/playwright-reporter

# WebdriverIO
pnpm add -D @brittlehq/wdio-reporter

# Jest
pnpm add -D @brittlehq/jest-reporter

# Vitest
pnpm add -D @brittlehq/vitest-reporter
```

## Wire it into your test config

Each framework has its own three-line wiring. The pattern is the same
everywhere: pass the hub URL and project token, leave everything else
to auto-detection.

```ts title="playwright.config.ts" ins={6-9}
import { defineConfig } from '@playwright/test';

export default defineConfig({
  reporter: [
    ['list'],
    ['@brittlehq/playwright-reporter', {
      url: process.env.BRITTLE_URL,
      token: process.env.BRITTLE_TOKEN,
    }],
  ],
});
```

For the wiring in WebdriverIO / Jest / Vitest, see the matching
[reporter](/docs/reporter/playwright) page — each one is a single
config-file edit.

## Run your tests

```bash
export BRITTLE_URL=https://brittle.dev          # or your self-hosted hub
export BRITTLE_TOKEN=brt_svc_xxxxxxxxxxxxxxxx
pnpm test
```

Sessions stream to the dashboard live as the suite runs.

## What ships with each session

- The test result: pass, fail, or skip.
- Whatever your framework captured: Playwright trace + video + HAR,
  WDIO screenshots + command log, Jest/Vitest stack traces.
- Per-test annotations (owner, severity, issue links) if you push
  them through your framework's annotation API.
- The git commit SHA, branch, and a few CI markers — picked up
  automatically from the working tree.

## Already not seeing results?

Two things to check before anything else:

1. **Token scope mismatch.** The token must belong to the project you
   expect runs to land in. If you have multiple projects, this is the
   most common stumble.
2. **Network reachability.** From the runner, `curl
   $BRITTLE_URL/health` should return `200`. Behind a corporate
   proxy, the reporter respects `HTTPS_PROXY` / `NO_PROXY`.

Set `BRITTLE_DEBUG=1` for verbose stderr logging; errors print with
the `[brittle]` prefix by default.
